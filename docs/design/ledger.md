### 2026-09-17 — command-stack-undo-redo — a gesture mutates more serialized props than the obvious one
- **Lesson**: Drag/Resize write the associated `pfdn:Label` (position + status) and flip `status` 0→2, not just the node's position. Any model-mutation or serialization change must enumerate the COMPLETE serialized write set per gesture (grep `features/` for `.set(`/`.position`/`.size`/`.status`/`.isReadOnly` exhaustively), or `toXML` residue survives after an inverse operation.
- **Evidence**: `packages/core/src/features/drag.ts:50-56,80-86`; design doc `docs/design/2026-09-17-command-stack-undo-redo/design.md` (capture set)

### 2026-09-17 — command-stack-undo-redo — derived state can be recomputed, not stored, when its producer is pure
- **Lesson**: The link waypoint router is a pure, fully-recomputed function of model position/size (`_setSideConnectors` allocates fresh `sides` each call and overwrites; `_routing` is scratch). Derived state with a pure producer should be recomputed on inverse/replay rather than captured — it avoids a two-writer race and stays byte-identical. Verify purity in code before relying on it; if the producer accumulates hidden state, the assumption is unsound.
- **Evidence**: `packages/core/src/modelling/Links.ts:231,263,348`

### 2026-09-17 — command-stack-undo-redo — an eslint token rule can't prove mutation totality
- **Lesson**: A lint rule keyed on a token (e.g. `definitions.*`) matches none of the real write sites — `collections.add/remove`, moddle `.set(`, and type-erased bare assignments (`(def.position as Point).x =`). Gate mutation/serialization totality on a `toXML` round-trip test (authoritative); keep lint as a cheap tripwire on named, syntactically-matchable primitives only.
- **Evidence**: `packages/core/src/features/drag.ts:81`, `packages/core/src/features/resizeElement.ts:74`; RFC ROADMAP.md:601-602

### 2026-09-18 — deterministic-ids-ssr — didi parses a default-arg constructor and crashes without $inject
- **Lesson**: A `['type', X]` didi service whose constructor gains ANY argument (even one with a default value) MUST declare `static readonly $inject = [...]`. didi's `parseAnnotations` regex parses the constructor and tries to `get()` the parsed param token, throwing "No provider" at boot — direct `new X()` construction in tests masks it. Verify against `didi/dist/index.js` (parseAnnotations / instantiate), not by assuming zero-arg construction.
- **Evidence**: `packages/canvas/src/ElementRegistry.ts:12`; `packages/canvas/src/Canvas.ts:31` ($inject precedent); didi `parseAnnotations`

### 2026-09-18 — deterministic-ids-ssr — "no browser" is not "no DOM"; install jsdom by add-only surface copy
- **Lesson**: The draw layer reads the GLOBAL `document`/`XMLSerializer`/`DOMParser`, not an injected Document, so a Node renderer must set `globalThis` from a jsdom and restore in `finally`. Copy jsdom `window`'s own-property surface ADD-ONLY (`!(key in globalThis)`) so JS intrinsics aren't clobbered (cross-realm `instanceof` breaks otherwise); hand-enumerating globals silently drops one (e.g. `DOMParser`, needed on every render via IconLoader). Render is synchronous after `await loadModel`, so the global-swap window is safe; a serial mutex covers overlapping calls.
- **Evidence**: `packages/canvas/src/Canvas.ts:11,105`, `packages/core/src/draw/IconLoader.ts:79`, `packages/canvas/src/SvgExportingUtils.ts:13`

### 2026-09-18 — deterministic-ids-ssr — a deterministic id generator must pre-claim author ids
- **Lesson**: `ElementRegistry.claimId` interleaves generation with author-set ids during the boot render loop, so a sequential generator can mint an id that collides with a later author id. Pre-claim every existing `element.id` in the loaded model (the four stamped collections node/link/label/zone) BEFORE boot; back the generator with a claimed-id Set that skips claimed ids. Model-presence ≠ claimed — verify the claim timing in the boot loop.
- **Evidence**: `packages/core/src/draw/BaseElement.ts:102,142-147`; `packages/canvas/src/ElementRegistry.ts:22-26`; `packages/editor/src/index.ts:43-44` (author-set node_1/label_1)

### 2026-09-18 — deterministic-ids-ssr — DEVIATION: dropped `@types/jsdom` for a scoped ambient shim
- **Lesson**: Plan Step 2 declared `@types/jsdom` as a devDependency, but the `registry.npmjs.org` metadata endpoint was 503 registry-wide during implementation (confirmed: even already-installed `vitest` 503'd on `/metadata`), so `@types/jsdom` could not be fetched. The renderer touches exactly one jsdom symbol (`new JSDOM(html, opts).window`), so a `packages/ssr/src/jsdom.d.ts` ambient `declare module 'jsdom'` covering just that slice is both leaner (no `@types/node`/`@types/tough-cookie` fan-out) and immune to a types-only package's registry availability. jsdom@25.0.1 itself was already lockfile-pinned + in the store; adding the `packages/ssr` importer edge to `pnpm-lock.yaml` by hand let `pnpm install --offline --frozen-lockfile` link it with zero metadata lookups. Promote to real `@types/jsdom` only if a future change needs more of jsdom's surface.
- **Evidence**: `packages/ssr/src/jsdom.d.ts`; `packages/ssr/package.json` (no `@types/jsdom`); `pnpm-lock.yaml` (`packages/ssr:` importer, `jsdom: 25.0.1`)

### 2026-09-18 — typed-event-bus — tsup/rollup-dts drops `declare module` blocks; type shared contracts as a plain exported interface
- **Lesson**: A cross-package TypeScript declaration-merge (`declare module '@d3-polytree/<pkg>' { interface X {…} }`) does NOT survive the tsup dts build — rollup-plugin-dts emits only the `src/index.ts` import-graph and drops standalone/ambient `declare module` blocks. Proof already in-repo: `packages/pfdn-moddle/src/moddle.d.ts`'s `declare module 'moddle'` is absent from `packages/pfdn-moddle/dist/index.d.ts` (grep exit 1). Because `turbo typecheck` is `dependsOn: ^build` (consumes deps' built `.d.ts`), a downstream augmentation would not even reach upstream local typechecks. So a shared type extended across packages (e.g. a bus `EventMap`) must be **one plain exported `interface` at the dependency sink** (canvas), not per-package augmentation — the plain-interface path is proven (`core/draw/types.ts:2` imports `RegisteredElement` from `@d3-polytree/canvas`, `DiagramElement extends RegisteredElement`). Verify dts propagation by grepping the BUILT `dist/index.d.ts`, never by assuming source `.d.ts` semantics carry through the bundler.
- **Evidence**: `packages/pfdn-moddle/src/moddle.d.ts:3` vs `packages/pfdn-moddle/dist/index.d.ts` (absent); `packages/core/src/draw/types.ts:2,14`; `turbo.json` (`typecheck` `dependsOn: ^build`); design `docs/design/2026-09-18-typed-event-bus/design.md`

### 2026-09-18 — typed-event-bus — a typed EventMap enforces at EMIT sites, not subscribe; and only where the field is retyped
- **Lesson**: Two traps when typing an `eventemitter3` bus via `EventEmitter<Map>`. (1) An interpolated `emit(\`${type}.${kind}\`, …)` over a UNION key only needs its args assignable to ONE constituent of the value-tuple union, so a key with a divergent payload (`.click` = `{ctrlKey?}|null` vs the other kinds' `Event`) is NOT enforced at that emit — enforcement bites at literal-key emits and (bivariantly, so weakly) on the subscribe side. (2) The map checks NOTHING at any call site whose field stays bare `EventEmitter` (default event types = `string|symbol`, no checking); real coverage requires flipping `EventEmitter → EventEmitter<Map>` at every declaration/injection site (~30 files here), so "add a map" is M-sized, not S. State enforcement claims precisely (emit-site key/arity/primitive payloads) and never oversell subscribe-side model precision that actually comes from each callback's own parameter annotation.
- **Evidence**: `node_modules/.pnpm/eventemitter3@5.0.4/.../index.d.ts` (`EventArgs`/`ArgumentMap` union indexing); `packages/core/src/features/mouseEvents.ts:46`; `packages/core/src/features/drag.ts:159` (annotation-borne subscribe precision)

### 2026-09-18 — typed-event-bus — RECON FIX: `elements.delete` is a bus event, not a command string
- **Lesson**: An early recon lumped `elements.delete` with the `commandStack` command strings (`element.create/delete/resize/move`) as "not a bus event." Wrong: `elements.delete` is emitted on the eventBus at `selection.ts:79` and subscribed at `Modelling.ts:109` (which then dispatches to `commandStack.execute`). The real boundary between the two vocabularies is "emitted on the eventBus" vs "handed to `commandStack.execute`", NOT the `element(s).` name prefix (`element.updated` is also a bus event). Classify each name by its actual emit/subscribe/execute site, never by prefix.
- **Evidence**: `packages/core/src/features/selection.ts:79`; `packages/core/src/modelling/Modelling.ts:109`; `packages/core/src/modelling/commands.ts:260-273`

### 2026-09-19 — orthogonal-link-routing — obstacle-aware routing breaks endpoint-locality; use commandStack.changed as the single reroute trigger
- **Lesson**: The current link router is endpoint-local, so the reroute trigger could be an incident-only `node.updated` subscription (`Links.ts:52-53,98-99`). Obstacle-avoiding routing makes a route depend on ALL node boxes, so a non-incident obstacle move — and node create/delete (which emit `.created`/`.removed`, never `node.updated`) — must also reroute. The complete, coalesced trigger is `commandStack.changed` (`CommandStack.ts:201-208`, fires once per top-level txn, symmetric execute/undo/redo) because post-O11 EVERY model mutation is command-mediated (verified: even properties-panel edits go through `element.updateProperties`, `PropertiesPanel.ts:200-216`, NOT a direct bus emit — an early recon misread said otherwise). Reroute must write waypoints via status-neutral `BaseElement.updateElement` (`:124`), NOT `reconcile` (whose `_builder` flips `status` 0→2, `:63-64`), or a status=0 link serializes `status="2"` and breaks the byte-identical toXML gate — and a status=1 (element.create) fixture MASKS it, so test with a status="0" fixture. Load-time `routeLinks` (`model.ts:63`) is the separate router for Viewer/InteractiveViewer/ssr (they boot no commandStack) and must ALSO skip pinned links.
- **Evidence**: `packages/core/src/command/CommandStack.ts:201-208`; `packages/editor/src/properties-panel/PropertiesPanel.ts:98-103,200-216`; `packages/core/src/draw/BaseElement.ts:63-64,124`; design `docs/design/2026-09-19-orthogonal-link-routing/design.md`

### 2026-09-20 — custom-element-react — importDiagram rebuilds the injector (new eventBus per boot); a consumer subscription needs a component-level stable surface
- **Lesson**: `Viewer._boot` `destroy()`s and rebuilds a new `Diagram`→`Injector`→`eventBus` on every `importDiagram`/`createEmpty` (`viewer/index.ts:114`, `Diagram.ts:42`), and `get('eventBus')` THROWS between destroy and the next boot. So a bus subscription taken via `get('eventBus')` dangles after any reboot. Adapter-side re-subscribe is INSUFFICIENT because engine-internal features reboot off the host instance, bypassing any adapter wrapper — verified: `localStorage.ts:40`, `upload.ts:61`, palette New `PaletteProvider.ts:111` all call `this._host.importDiagram/createDiagram()`. The fix is a stable `on/off` on the long-lived component: a registry of (event,handler) pairs + a HELD `_bus` ref, re-attached in `_boot` after `new Diagram`; split a private `_teardown()` (detach via the held ref, keep registry) from public `destroy()` (teardown + clear). Scope the typed surface to POST-BOOT events (`document.changed`/`selection.changed`/`commandStack.changed`) — drawers fire the initial `*.created` synchronously during `new Diagram`, before re-attach, so a general `on('node.created')` silently drops the initial model. Bonus: routing `_boot` through the non-virtual `_teardown()` (not virtual `this.destroy()`) fixes a latent bug where a reboot stripped `Editor`'s ctor-added undo/redo keydown listener.
- **Evidence**: `packages/viewer/src/index.ts:114`; `packages/core/src/features/localStorage.ts:40`, `upload.ts:61`, `features/palette/PaletteProvider.ts:111`; `packages/editor/src/index.ts:84,115-117`; design `docs/design/2026-09-19-custom-element-react/design.md`
