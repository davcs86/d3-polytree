# Design: c10-lod-zoom-out

**Created**: 2026-10-08
**Depth**: deep
**Rounds**: 3 (termination: approved)
**Approved by**: user @ 2026-10-08 (round-3 gate)
**Grounded in**: recon.md (this directory; includes two measured spike sections) and the predecessor `docs/design/2026-10-06-c10-spatial-index-culling-perf/{recon,design,plan,measurements}.md`

**Amendment A2** to the C10 design. It **supersedes** predecessor `design.md` §3 "LOD (PR3)" (label-only LOD below scale 0.3) and §11 "PR3 — LOD + ceiling" (`design.md:58`, `:127`), after PR1/PR2 measurements showed label-only LOD removes ≈4% of what is painted at fit-all.

---

## Chosen Approach

**"Stage 1, reduced": a boolean _LOD state_ inside `Culling`.** While the state is ON, an in-view **node or link** slot that is not exempt is treated exactly like a culled slot — it carries the existing `data-pfd-transient="culled"` and the existing CSS rule hides its paint. Labels and zones are never LOD'd. There is **no new attribute value, no CSS change, no export-strip change and no `_checkCss` change** (`_culling.scss:7` matches any value; `SvgExportingUtils.ts:19` strips any value). `<g>`, `<title>`, `<desc>` and `tabindex` survive, so AT-discoverability (not waived) is kept. The kill switch is the existing `culling` boolean: `culling:false` also disables LOD (to be stated in the READMEs). It is called "LOD state", never a mode or option (predecessor rejected modes, `design.md:138`).

**Evidence for the representation (recon "Spike results", local/unpinned, n = 2–3, quantised to 16.7 ms):** hiding all painted children of nodes + links at fit-all (23k fixture, scale 0.1) takes pan p95 from ≈283 → 50–83 ms; keeping a placeholder (node rect + main link path) recovers only ≈20% (283 → 217–233); nodes-only 217, links-only 167. A container-level attribute flip is **not** O(1) (1.2–3.1 s single task) and was rejected. Zoom-tick cost (180–530 ms) is **not** improved — LOD buys **settled pan only** (≈4×).

**One predicate drives every pass:** `hold(slot) = lod && kind∈{node,link} && (flags & (SEL|FOCUS|FRESH)) == 0`.

- SHOW reveals iff `inside && !hold`; HIDE hides iff `!inside || hold`. Eligible in-view slots that pan in while ON are **not** revealed; ineligible kinds and exempt slots keep the synchronous SHOW (the predecessor "SHOW is never late" rule holds for everything the state does not deliberately hold).
- **Per-slot state** (parallel typed arrays grown with `_culled`, indexed by `FlatIndex` slot): `_kind` (1 node, 2 link, 3 label, 4 zone; written only in `_onCreated` from the closure's `cls`, `culling.ts:105` — never from a `.removed` payload, which can be a bare `{id}`, ledger c2), `_flags` (SEL, FOCUS, FRESH), `_defs`/`_els` (for the resolver). **On `_onRemoved` every per-slot field, the admitted list/counter, the fresh list and `_focusSlot` are cleared** (the free-list reuses slots LIFO, `FlatIndex.ts`), and `_onCreated` resets flags and asserts them zero.
- **Trigger (scale only — no count term, no wall-clock dwell, PLAT-06):** ON is evaluated statelessly in every `_frame` as `!_inGesture && !lod && _mayRun() && scale ≤ LOD_SCALE_ON` (no `_lodEvalPending` flag); a frame is requested on `zoom.end` (skipped when `!_mayRun()`). `_inGesture` is set by `zoom.start` and cleared by `zoom.end`/destroy (a stuck `start` self-heals on the next gesture; worst case LOD stays off = today's behaviour). Programmatic `setZoom` emits no start/end, so `canvas.zoomed` outside a gesture also requests a frame. **OFF is synchronous**: `_onZoomed` checks `lod && scale > LOD_SCALE_OFF` **before** the `!_mayRun()` early return and before the SHOW scan, sets `lod=false`, and the existing scan reveals every in-view held slot in the same tick (user decision: accept a one-time reveal task; ~48–110 µs per element, measured in the reveal set at the exit scale only). `_frame` also enforces OFF defensively.
- **Entering LOD** is budgeted: held hides share the single ascending-slot `HIDE_BUDGET` (300) with off-screen hides; `idle` is set to `'false'` on the flip and stays `'false'` while any hold backlog remains; E (in-view painted eligible slots) is read from `inspect()` by the gates, not hard-coded (recon quotes 4.1k–9.6k; spike S0-4 reconciles it).
- **Observability:** container attribute `data-pfd-lod="off|entering|on"` (outside the `<svg>`, never exported, absent when inert, like `data-pfd-culling-idle`); `inspect()` gains `lod:{state,held}` and per-slot `kind`, `exempt`, `hold`.
- **Constants** (`spatial/types.ts`, `@internal`, **provisional, product judgement**): `LOD_NODE_PX` 25 (moddle default), `MIN_LEGIBLE_PX` 4, `LOD_SCALE_ON` = 4/25 = **0.16**, `LOD_SCALE_OFF` = 5/25 = **0.20**, `LOD_EXEMPT_CAP` 200, `LOD_CLICK_TOL_PX` 4. Nothing was measured at 0.16/0.20 (spikes ran at 0.1); a diagram of larger nodes loses them at 16 px — documented limitation. A mockable test seam follows `culling.test.ts:12-16`.

**Exemptions (state-based; no CSS):**

- _Selection_: `selection.changed` handler reads **only `snapshot`** (`prev` is taken after a clear and `deleteSelected` emits nothing, `selection.ts:63-88`), reads `definition.id` defensively, admits wanted slots in **ascending slot order, sticky, up to `LOD_EXEMPT_CAP`** (user decision: first-N, no suspend cliff); a newly admitted slot is revealed via an O(1) bounds-vs-viewport test; beyond the cap selected elements keep `.selected` but lose their indicator (documented). Selected-node incident links stay hidden (documented).
- _Focus_: `focusin`/`focusout` on the container; one slot flagged; idempotent. `focusout` is not relied on for release on removal (Firefox/Safari do not blur on removal) — `_onRemoved` clears the flag.
- _Fresh_: `_onCreated` sets FRESH only while `lod` is ON (the boot storm happens with LOD off), capped at `LOD_EXEMPT_CAP`, cleared at the next viewport change (no wall clock) — covers undo-of-delete and palette-add; an undo restoring more than the cap leaves the remainder hidden (documented).

**Click/dblclick resolution through the spatial index (user steering) — `Culling._onPointer`:**

- A **capture** listener on `canvas.getContainer()` (below d3-drag's window-capture `click.drag` suppression, so a pan-drag-release never reaches it — verified `d3-drag nodrag.js` `yesdrag`, `d3-zoom zoom.js:295-300`; above the root-layer bubble handlers `background.click` and `dblclick.zoom`, `zoom.ts:151-164`).
- Guards: `lod && _mayRun()`; the **link tool is not active** (root-layer `cursor-add-link` class — user decision, `AddLinkTool` listens to `node.click`); pointer-originated only: `event.detail > 0` **and** (where available) `pointerType`; a click whose own target is a held slot's `<g>` is never a pointer click (a held slot has no hit area) → native dispatch, so keyboard/AT-synthesised clicks are unaffected; target inside the main svg.
- Pick order: native target inside a visible node → native; hidden-node hit; native target inside a visible **label or zone** (labels are the only text the eye sees at LOD) → native; hidden-link hit; else native. Hit test: world point via `d3.pointer(event, svgNode)` then the persisted `(p − t)/s` (correct under CSS-transformed hosts; same as `AddLinkTool`), tolerance `LOD_CLICK_TOL_PX / s`, candidates from `FlatIndex.scan` in ascending slot order, nodes by true-footprint containment (rank distance to centre, then lowest slot), links by min point-to-segment distance over `_defs[slot].waypoint` (direct property reads, ledger 2026-09-20), accept `d ≤ lineWidth/2 + tol`; no Map iteration (PLAT-06).
- **Mark-and-skip handoff (user decision):** the resolver emits `${cls}.click` / `${cls}.dblclick` on the bus with `(els[slot], defs[slot], originalEvent)` (the `MouseEvents` shape, `mouseEvents.ts:46-50`, so `Selection` sees ctrl/meta) and records the event in a module-level `WeakSet`; `zoom.ts`'s background-click handler (`:151-162`) skips marked events. **Nothing is swallowed**: d3-zoom's dblclick-zoom still zooms 2× exactly as for a visible node, and host document-level listeners still see the click. Touch double-tap bypasses the DOM event (`zoom.js:386-392`) and is unaffected. Documented: no hover, drag, resize, context menu or link-tool pick until zoomed in.
- Typing note (ledger 2026-09-18): `emit(`${cls}.click`)` is only weakly type-enforced; the A2 note must not oversell it.

**Gates (behavioural, not syntactic — ledger 2026-09-17):**

- _Unit/property (vitest, injected events, rAF stub, no timers)_: resolver cases (hit, miss, tie-break, ctrl-click, `detail:0` native, held-`<g>` target native, link-tool guard, mark-and-skip, dblclick); the editor property test gains ops (`setInitialZoom` to 0.12/0.18/0.5 through the real d3 path, bus clicks, `focusin`, resolver click, creates/removes/undo) and the stale pan/zoom op range (`0.3 + rnd*1.7`) is extended to reach LOD. Invariants at idle: `culled == (!intersects(padded) || hold)`; `data-pfd-lod` equals a replayed hysteresis model; labels/zones never culled in view; `exempt ⊆ (Selection snapshot ∪ activeElement slot ∪ fresh)` computed independently of Culling's flags (catches ghost exemptions from slot reuse); admitted ≤ cap and sticky; every in-view selected node/link up to the cap painted; resolver click selects the brute-force-expected id; **synchronous exit** (no flush) leaves no in-view eligible slot hidden; ≤ 3 toggles per element per op; hide budget respected; the old invariant "culled ⇒ not in padded viewport" is rewritten.
- _Playwright_: G1 becomes per-slot `attribute ⇔ (!inside ∨ (lod ∧ eligible ∧ ¬exempt))` (exempt set from Selection and `activeElement`), not "allowed whenever LOD != off"; existing `STATES` at 0.12 now exercise LOD through programmatic `setZoom`, so a **harness-only `@internal` LOD kill switch** (not a public option, user decision) keeps one 0.12 state with LOD forced off to preserve a faithful node/link culling oracle; the sync-exit check sets the zoom and reads the DOM in **one** `page.evaluate`; tween cases use `reducedMotion:'no-preference'`; G2 bounds apply to the ineligible-or-exempt subset; G3 allows culled→lod→visible→culled (3 toggles); `settled()` relies on `idle='false'` set on the flip; new LOD cases (real enter/exit, hysteresis, bounded per-frame drain, real-mouse click on a hidden node selects it and shows its outline, ctrl-click adds, cap, pan-drag-release does not select, native visible exempt keeps native dispatch, dblclick records `node.dblclick` AND zooms, label click wins over a nearby hidden node, link tool unaffected, focus+arrow nav paints the target, undo-of-delete stays visible then hides after a viewport change, G4 AX and G5 export parity re-run with LOD on, a no-flush tween from 0.1 to 1.2 exits LOD without a wrongly-culled sighting).
- _Perf_ (`perf.spec.ts`, `perf-budget.json`): a **fit-all pan arm** and a **crossing arm** (long-task observer: max single task + max rAF delta for the enter drain and the sync exit); the LOD-off baseline comes from the same build via the `@internal` kill switch (no merge-base double build). **User decision: a pinned measurement of the REAL per-slot mechanism (≥ 5 pinned runs, separation safeguard `off median − on max ≥ 2 × on-arm spread`) is a merge go/no-go**; budgets become blocking (predecessor G-DF2) once measured; if separation fails the arm returns to the user. Local numbers are not budget evidence.

**Stated plainly for the user (fork, DF-2):** Stage 1 will **not** reach the 33 ms goal — the floor is ≈ 50–83 ms local from the ≈ 10k hidden-child `<g>` boxes themselves; the fit-all topology is **blank** (nodes/links invisible, labels/zones remain); hover/drag/resize/context menu are unavailable until zoomed in. Accept a pinned ≈ 50–67 ms budget, or fund a Stage 2 (below).

**Delivery order (user decision):** step-0 spikes (including the pinned measurement of the real mechanism) → LOD core + exemptions + gates → **resolver as a separate reviewable step**; changesets: core minor, interactive-viewer/editor/viewer patch (README/JSDoc-only edits require a patch, root `CLAUDE.md`); also amend the still-pending `.changeset/c10-viewport-culling.md` (LOD ships in the same release); update `packages/{core,interactive-viewer,viewer,canvas}/CLAUDE.md`, `apps/storybook/CLAUDE.md` + `docs/context-constitution.md`, the ROADMAP C10 row, and record the supersession of label-LOD (including that labels/zones stay painted at 0.1–0.16 where they are illegible). The `LOD_*` constants are exported from the `@d3-polytree/core` root through `spatial/index.ts` — a de-facto public surface despite `@internal`.

**Step-0 spike list (before code):** S0-1 event trace (`zoom.start/zoom/end`/`canvas.zoomed` for `setInitialZoom` ± duration, `setZoom`, `zoom.to.element` zoomable/not, wheel, bare click); S0-2 listener order (drag-release sees no click; mark-and-skip leaves dblclick zoom intact); S0-3 `event.detail`/`pointerType` for Playwright click/dblclick, keyboard Enter, `el.click()`, CDP AX default action (Chromium only; AT correctness is not CI-gateable — manual pass outstanding, ledger c2); S0-4 observed E at fit-all and the drain/exit tasks at the 0.20 exit viewport on small and large screens; S0-5 scale sensitivity at 0.16/0.20/0.25 + human legibility check + thrash around the 0.16–0.20 band; S0-6 resolver ambiguity at 4 px; S0-7 `content-visibility` on SVG `<g>` (gates Stage 2 only); S0-8 pinned measurement of the real per-slot mechanism.

## Rejected Alternatives

- **Label-only LOD at scale 0.3 (predecessor PR3)** — rejected: removes ≈4% of painted elements at fit-all (recon "Measured evidence"); superseded by this amendment.
- **Container-attribute CSS LOD (single flip)** — rejected: the flip is a 1.2–3.1 s single long task in either direction (spike 1), not O(1) (round-1 panel: target-state and performance-first angles).
- **Placeholder representation (node outline rect as a filled square + main link path)** — rejected: recovers only ≈20% (283 → 217–233 ms, spike mode B); fails its own go/no-go (round-1 minimal-delta angle).
- **Per-slot `'lod'` attribute value with a tri-state** — rejected: adds relabel writes, budget double-counting, a new CSS/`_checkCss` surface and a G1 that must become value-aware, with no observable gain over holding on `'culled'` (round 2).
- **Count-based trigger (in-view eligible count with hysteresis) and a wall-clock dwell** — rejected: needs a per-slot kind scan on the zoom path, thrashes on clustered diagrams, a wall-clock dwell breaks PLAT-06 and makes `settled()` racy; blanks legible-scale views (round 2 adversary).
- **Budgeted centre-out OFF drain** — rejected by the user (round-2 gate) in favour of a synchronous exit: keeps "SHOW is never late" and removes the mid-drain idle/click complexity; cost is a one-time reveal task.
- **Suspend LOD above the selection cap** — rejected by the user: a performance cliff on select-all.
- **Aggregate LOD layer (one `<path>` for in-view links, one for nodes, built from the spatial index)** — rejected for this change: a new rendering path (~2× the PR: `LodGeometry`, layer build/strip, hit-test, `FlatIndex.hit`), does not lower the ≈10k hidden-`<g>` floor, every number unmeasured; it would restore a readable topology and make SHOW budgetable. **Deferred as a separately gated Stage 2** (previously waived canvas overlay re-evaluated at the user's request, verdict: additive, not a replacement).
- **`content-visibility: hidden` / `will-change: transform`** — layer promotion hurt (spike 2); `content-visibility` looked best for zoom ticks (n = 2, noisy) but is unverified on SVG `<g>` and might drop `<title>`/`<desc>` from the AX tree → deferred behind S0-7.
- **`stopPropagation` in the resolver** — rejected by the user in favour of mark-and-skip: it would remove dblclick-zoom on hidden nodes (parity break; no in-repo consumer of `*.dblclick`) and hide clicks from host listeners; touch double-tap bypasses it anyway.
- **Merge-base baseline run for the LOD-off control** — rejected by the user in favour of an `@internal` harness kill switch + pinned go/no-go: double build, floating baseline.
- **"Measurement + documented ceiling only"** — kept as the fallback if the pinned go/no-go fails the separation safeguard.

## Open Risks

- [ ] Settled-pan-only yield (≈4×) and a ≈ 50–83 ms floor miss the 33 ms binding goal; zoom ticks unimproved — resolved by the pinned go/no-go (S0-8) and the user's 33 ms fork; **budgets TBD from ≥ 5 pinned runs** (impl-plan step 0 / perf step).
- [ ] The shipped per-slot mechanism was never measured end to end (spikes used a CSS simulation + drain emulation); local numbers are quantised (16.7 ms), n = 2–3, unpinned — S0-8.
- [ ] E (in-view eligible count at fit-all) is unreconciled in the docs (4.1k vs 9.6k) — S0-4; enter/exit timings are ranges until then.
- [ ] Constants S_ON/S_OFF/`MIN_LEGIBLE_PX`/cap/tolerance are provisional product judgements; the 0.16–0.20 band is only 1.25× (≈ 2–3 wheel notches) and each flip is O(E) — thrash must be measured (S0-5); exit cost is the reveal set at 0.20 (≈ E/4 on the same screen, up to the whole diagram on a 4K screen).
- [ ] `event.detail`/`pointerType` as the pointer-vs-AT discriminator is verified only in Chromium; real AT default-action dispatch in Safari/Firefox is not CI-gateable (ledger c2) — manual AT pass outstanding.
- [ ] Hit-test z-order and tolerance can diverge from what the eye would have hit (the eye sees nothing at LOD); mitigated by label/zone-first native pick order and deterministic tie-break; S0-6 measures ambiguity.
- [ ] Pre-existing zone `getBBox` gap in Outline (culled-and-updated zone measures 0×0, `outline.ts:55-60`) is untouched (zones/labels are never LOD'd) — follow-up.
- [ ] Selected-node incident links / selected-link endpoints are not exempt → an isolated node/link at fit-all; the first-N cap loses the indicator beyond 200; an undo restoring > 200 deleted elements leaves the rest hidden — documented, user-visible.
- [ ] Accessibility contrast of any exempt visuals at fit-all has no automated check (ledger theming) — hand-check in the plan.
- [ ] Stage 2 (aggregate layer) is deferred; revisit only after the pinned results.
