## Feature gaps

### Palette "Save" has no restore path — P0 · leverage H ÷ XS

- **Surface element:** Editor palette entry `save` → `LocalStorage.save()` at `packages/core/src/features/localStorage.ts:45` (palette wiring `packages/core/src/features/palette/PaletteProvider.ts:118-123`).
- **The gap:** the inverse `LocalStorage.loadSaved()` (`localStorage.ts:37`) is called only from `packages/core/src/features/fileio.test.ts:43,48` — no palette entry, component method, boot hook, adapter, or Storybook story calls it (grep `loadSaved` across `packages/` + `apps/`). A user clicks Save, sees "Diagram saved" (`localStorage.ts:47`), and has no way to get it back.
- **Trigger (P0):** important (a user-facing contract that misleads — implied persistence that isn't) × urgent (live in every Editor today).
- **Trade-off — building it:** an "Open saved" palette entry or `loadSaved` opt-in on boot is ~a dozen lines; adds one more storage-state edge case (stale/invalid stored XML). **Not building it:** users lose work they believe was saved; the button is actively misleading.

### Adapters cannot compose modules (icon packs, custom modules) — P1 · leverage H ÷ S

- **Surface element:** `<d3-polytree-editor>` constructs `new Editor({ container })` at `packages/element/src/index.ts:58`; React `PolytreeEditor` at `packages/react/src/index.tsx:105`.
- **The gap:** `ViewerOptions.modules` (`packages/viewer/src/index.ts:55`) — the documented single extension seam (root `README.md` custom-module section; CLAUDE.md DI invariant 1) — is unreachable through either adapter (grep `modules` in `packages/element/src`, `packages/react/src`: none). `awsIconsModule` therefore cannot be used from the adapters.
- **Trade-off — building it:** a `modules` property/prop forwarded at construction; must define reboot semantics (modules are boot-time only). **Not building it:** adapter consumers are locked to the default icon set and no custom behaviour — the adapters are the "largest adoption unlock" per ROADMAP C7.

### Adapters are editor-only — no viewer / read-only mode — P1 · leverage H ÷ M

- **Surface element:** `packages/element/src/index.ts:58`, `packages/react/src/index.tsx:105`; no `readonly`/`mode` attribute or prop, no `<d3-polytree-viewer>`/`PolytreeViewer` (grep `readonly|readOnly|mode|PolytreeViewer|d3-polytree-viewer`: none).
- **The gap:** embedding a read-only diagram — the common case, and the Track D sidebar/host scenario (ROADMAP §13) — requires dropping to the raw `Viewer` class and losing the adapter's shadow-DOM/styles/form bridge.
- **Trade-off — building it:** a second element + React component (or a `mode` switch that reboots with a different class) — more bundles/tests to maintain. **Not building it:** adapter users ship full editing chrome where they only want display, or re-implement the adapter.

### `@d3-polytree/diff` ships only half of C5 — P1 · leverage M ÷ M

- **Surface element:** `diff(a, b): DiffOp[]` is the sole export (`packages/diff/src/index.ts:9`); header comment and README (`packages/diff/README.md:4-6`) advertise "review overlay or three-way merge helper".
- **The gap:** no apply/patch, three-way merge, or overlay (grep `applyDiff|applyOps|patch(|merge3|threeWay|Overlay`: none in `packages/*/src`). ROADMAP C5 (`ROADMAP.md:527`) promises the overlay with ghosted positions and a git three-way helper; C1's "diff-apply" motivation (`ROADMAP.md:523`) has no consumer.
- **Trade-off — building it:** `applyDiff` via one `commandStack` transaction (atomic, one undo — the seam already exists) then an overlay layer; M/L effort. **Not building it:** the package is an unconsumed primitive; README over-promises.

### Dirty flag never resets on save; no unsaved-changes guard — P1 · leverage M ÷ S

- **Surface element:** `document.changed` payload `{ dirty: canUndo }` at `packages/core/src/command/CommandStack.ts:237-243` (comment: "Save-baseline reset … is a deferred refinement"); surfaced via `Viewer.on` and React `onChange({ dirty })` (`packages/react/src/index.tsx:112-117`).
- **The gap:** after Save/Download, `dirty` stays `true` until the stack is empty; no `markSaved()`/save-point API, no `beforeunload` guard (grep `markSaved|savePoint|beforeunload`: none).
- **Trade-off — building it:** a save-point index on `CommandStack` + a `markSaved()` method; small, but touches the transactional core (needs round-trip tests). **Not building it:** consumers cannot build a correct "unsaved changes" indicator — the flag they are given is wrong after the first save.

### No keyboard actions on the focused element (Delete, Enter, move) — P2 · leverage M ÷ S

- **Surface element:** `keyboardNav` handles arrows + Escape only (`packages/core/src/features/keyboardNav.ts:113-124`); Editor keydown handles Z/Y only (`packages/editor/src/index.ts:98-112`).
- **The gap:** Delete/Backspace do nothing (grep `'Delete'|'Backspace'`: none); deletion is palette/`deleteSelected()`-only; no keyboard move. Keyboard users can navigate (C2) but not edit.
- **Trade-off — building it:** a small keymap in Editor routed through existing commands (undoable for free). **Not building it:** the editor stays mouse-only for mutation, an a11y gap under C2's WCAG goal.

### No copy / paste / duplicate — P2 · leverage M ÷ M

- **Surface element:** Editor API (`packages/editor/src/index.ts:121-210`) and palette (`PaletteProvider.ts:99-184`).
- **The gap:** grep `copy|paste|clipboard|duplicate`: no hits in component/feature sources.
- **Trade-off — building it:** id-remapping + link re-attachment in one `createElement` batch transaction. **Not building it:** users rebuild repeated sub-flows by hand — the most expected editor affordance after undo.

### No marquee selection or select-all — P2 · leverage M ÷ S

- **Surface element:** selection is click / ctrl+click only (`packages/core/src/features/selection.ts:50-56`).
- **The gap:** grep `marquee|lasso|rubber|brush|selectAll` (excluding d3 `.selectAll`/private `_unSelectAllElements`): none. Multi-element gestures (C1 atomic delete/move) have no efficient way to build the selection.
- **Trade-off — building it:** a d3-brush over the canvas, conflicting with pan-drag (needs a modifier). **Not building it:** bulk edits require N ctrl+clicks.

### JSON documents have no path into the components — P2 · leverage M ÷ S

- **Surface element:** `loadModelFromJson` (`packages/core/src/model/model.ts:85-103`) vs component API `importDiagram(xml)` / `exportDiagram()` (`packages/viewer/src/index.ts:120,135`); `Upload` reads `.pfdn` XML only (`packages/core/src/features/upload.ts`); `ExportFormat = 'pfdn'|'svg'|'png'` (`packages/core/src/features/exporting.ts:10`).
- **The gap:** C11 shipped the JSON adapter, but no component, adapter, or `ssr.renderToSvg` accepts JSON (grep `loadModelFromJson|importJson|exportJson` outside core model: none).
- **Trade-off — building it:** `importJson`/`exportJson` on `Viewer` (thin — validate-first path exists). **Not building it:** JSON consumers must round-trip through XML themselves, undercutting C11.

### No fit-to-view / zoom controls on the component API — P3 · leverage L ÷ XS

- **Surface element:** zoom is reachable only via `viewer.get('zoom').setZoom(…)` (`packages/core/src/features/zoom.ts:78-167`).
- **The gap:** no `fitToView`/`zoomIn`/`zoomOut`/`resetZoom` method, palette entry, or `+`/`-`/`0` keys (grep `fitToView|zoomToFit|fit(`: none).
- **Trade-off — building it:** thin wrappers + palette entries. **Not building it:** large diagrams open at arbitrary zoom; users must discover wheel-zoom.

### UI strings are hard-coded English — P3 · leverage L ÷ M

- **Surface element:** palette titles (`PaletteProvider.ts:102-179`), toasts (`localStorage.ts:47,62`), SVG label "Process flow diagram" (`keyboardNav.ts:109`).
- **The gap:** no translate/i18n hook (grep `i18n|translate(|locale`: only `localeCompare`). The aria labels (C2) are English-only too.
- **Trade-off — building it:** a didi-overridable `translate` service (diagram-js pattern — fits the "last definition wins" seam). **Not building it:** non-English hosts cannot localize chrome or screen-reader output.

## Inconsistencies

### `@d3-polytree/ssr` README vs its published shape — P1 · leverage H ÷ XS

- **Sibling surfaces:** `packages/ssr/README.md:15-17` ("No peer dependencies … engine packages (`viewer`, `core`, `canvas`) are bundled into `dist` … No D3 v7 slices to add") vs `packages/ssr/tsup.config.ts` (`external: ['jsdom']`, no `noExternal`) + `packages/ssr/package.json:27-31` (engines as regular deps, no D3 peers). A local build of `ssr` emits `dist/index.js` with `import … from "@d3-polytree/canvas"` ×2, `"@d3-polytree/core"`, `"@d3-polytree/viewer"` — **not bundled**.
- **User impact:** the engines' D3 slices are **peers** of `viewer`/`core` (`packages/viewer/package.json` peerDependencies); following the README ("No D3 v7 slices to add") can leave them unresolved at runtime under strict installs. **Fix trade-off both ways:** correcting the README (declare/document the D3 peers) is XS; bundling instead grows the package but matches the promise. Leaving it misleads every Node consumer.

### `Viewer.on` advertises events that never fire in Viewer / InteractiveViewer — P1 · leverage M ÷ S

- **Sibling surfaces:** `ReboundEvent = 'document.changed' | 'selection.changed' | 'commandStack.changed'` on the base `Viewer` (`packages/viewer/src/index.ts:30`) vs `commandStackModule` arriving only via `modellingModule` (`packages/core/src/modelling/index.ts:57`), composed only by `Editor` (`packages/editor/src/index.ts:62`); `selectionModule` is only in `InteractiveViewer.interactionModules`.
- **User impact:** in `Viewer`, all three subscriptions register silently and never fire; in `InteractiveViewer`, two of three. **Fix trade-off:** narrow the type per subclass (breaking for type consumers) vs document per-class availability (cheap, leaves a footgun).

### Modifier keys disagree (Ctrl-only multi-select vs Ctrl/Cmd undo) — P2 · leverage M ÷ XS

- **Sibling surfaces:** undo/redo accept `ctrlKey || metaKey` (`packages/editor/src/index.ts:98`) vs multi-select checks `ctrlKey` only (`packages/core/src/features/selection.ts:54`, `packages/core/src/features/drag.ts:171`).
- **User impact:** on macOS, Cmd+click (the platform convention) does not multi-select, while Cmd+Z does undo. **Fix trade-off:** accept `metaKey` (XS; must not collide with d3-drag's filter) vs leave Mac users without a discoverable multi-select.

### Adapter change contracts diverge — P2 · leverage M ÷ S

- **Sibling surfaces:** element `change` → `detail: string` (eager serialize, no `dirty`) at `packages/element/src/index.ts:25-30`, and no selection/commandStack event; React `onChange({ dirty, getValue })` (lazy) at `packages/react/src/index.tsx:112-117` + `onSelectionChange` at `:119-125`.
- **User impact:** switching adapters changes payload shape and event coverage; the element serializes the whole document on every change. **Fix trade-off:** align on `{ dirty, value }` + a selection event (breaking for element listeners) vs document the difference.

### Element `value` setter silently resets history — P2 · leverage M ÷ XS

- **Sibling surfaces:** element `value` re-imports on every external set (`packages/element/src/index.ts:81-99`) vs React which is deliberately uncontrolled **and says why** — "destroys history" (`packages/react/README.md:18-26`); the element README (`packages/element/README.md:77`) has no such warning.
- **User impact:** a host that echoes `value` back (a common two-way-binding pattern) wipes undo + selection. **Fix trade-off:** a README warning (XS) vs a no-op-on-equal guard (the echo guard exists; external equal sets still re-import).

### Error contracts differ across sibling APIs — P2 · leverage M ÷ M

- **Sibling surfaces:** `fromJson` returns a `Result` but throws `TypeError` on non-objects (`packages/pfdn-moddle/src/json.ts:421-425`); `loadModelFromJson` throws `PfdnValidationError` (`packages/core/src/model/model.ts:103`) — not re-exported from `core` (`packages/core/src/index.ts`); `diff` throws `DiffError`; `Exporting.trigger` only `console.error`s an unknown format (`packages/core/src/features/exporting.ts:51`); Editor `undo`/`redo` throw `"no diagram loaded"` pre-load (`packages/viewer/src/index.ts:148-151`) though documented "No-op if nothing to undo" (`packages/editor/src/index.ts:192-199`).
- **User impact:** each call site needs a different error strategy; core-only consumers cannot `instanceof`-check the error core itself throws. **Fix trade-off:** one documented contract (result vs throw) is a cross-package decision (M, possibly breaking) vs per-API docs.

### Strict vs lax defaults differ by format — P2 · leverage L ÷ XS

- **Sibling surfaces:** `fromXML` forces `lax: true` (`packages/pfdn-moddle/src/PfdnModdle.ts:52`) vs `validate`/`fromJson`/`loadModelFromJson` strict by default (`json.ts:213,421`, `model.ts:85-91`).
- **User impact:** the same invalid document loads from XML but is rejected from JSON. **Fix trade-off:** document the asymmetry (XS) vs unify defaults (behaviour change for one path).

### `@d3-polytree/react` install contract is incomplete — P2 · leverage M ÷ XS

- **Sibling surfaces:** `packages/react/package.json:27-33` declares only `@d3-polytree/editor` + React peers, and its README install (`packages/react/README.md:13`) omits D3 slices — vs `@d3-polytree/element` README (`packages/element/README.md:15`) and the three components, which declare the six D3 peers (per the README template rule). The React usage also imports `@d3-polytree/interactive-viewer/style.css` (`packages/react/README.md:33`), not a declared dependency.
- **User impact:** strict package managers (pnpm) can fail to resolve the D3 peers or the stylesheet. **Fix trade-off:** declare peers + dependency (XS) vs leave first-install friction.

### Load/export naming drift across layers — P3 · leverage L ÷ S

- **Sibling surfaces:** engine `importDiagram`/`exportDiagram`/`createEmpty` vs Editor `createDiagram` (`packages/viewer/src/index.ts:120-145`, `packages/editor/src/index.ts:122`) vs React handle `load`/`export` (`packages/react/src/index.tsx:34-41`) vs element `value`/`exportSVG()`; adapters boot `createEmpty()` while READMEs' quick starts use `createDiagram()` (root `README.md:51`).
- **User impact:** mild — every layer needs its own vocabulary. **Fix trade-off:** aliases (API growth) vs doc cross-reference table.

## Recommended features (additive)

### `<d3-polytree-viewer>` + `PolytreeViewer` with a `modules` passthrough — P1 · leverage H ÷ M

- **Motivated by:** editor-only adapters (`packages/element/src/index.ts:58`, `packages/react/src/index.tsx:105`), Track D read-only embedding (ROADMAP §13).
- **What / why:** read-only and interactive-viewer adapters sharing the editor adapter's shadow-DOM + style pipeline; a `modules` property on all of them.
- **Trade-off — building:** unblocks the embed/Track D path and icon packs for adapter users. **Not building:** adopters needing display-only must bypass the adapters entirely.

### `applyDiff` + review overlay on the command stack — P1 · leverage M ÷ L

- **Motivated by:** `diff()` (`packages/diff/src/index.ts:9`) with no consumer; C1's atomic transaction seam.
- **What / why:** apply a `DiffOp[]` as one undoable transaction, then render ghosted prior positions — the "visual merge" C5 promised.
- **Trade-off — building:** earns the O1 XML decision; L effort, overlay needs VR coverage. **Not building:** diff stays a library curiosity.

### Save points: `markSaved()` + opt-in `beforeunload` guard — P2 · leverage M ÷ S

- **Motivated by:** `document.changed { dirty: canUndo }` (`CommandStack.ts:237-243`), palette Save (`PaletteProvider.ts:118-123`).
- **What / why:** a correct dirty flag after save; hosts get a trustworthy unsaved-changes indicator.
- **Trade-off — building:** small change in the transactional core (needs round-trip tests). **Not building:** every host builds its own, wrong, dirty tracking.

### Editor keymap + in-app shortcut help — P2 · leverage M ÷ S

- **Motivated by:** keyboardNav (arrows/Escape) and Editor keydown (Z/Y) as the only bindings (`keyboardNav.ts:113-124`, `editor/src/index.ts:98-112`).
- **What / why:** Delete/Backspace, Ctrl/Cmd+A, Ctrl/Cmd+C/V/D, `+`/`-`/`0` zoom/fit, and a `?` overlay listing them — closes the keyboard-editing a11y gap and the discoverability gap together.
- **Trade-off — building:** keymap conflicts with host pages (scope to the focused container, as undo already is). **Not building:** mouse-only editing; features stay unfound.

### `renderToSvg` sizing options (`width`/`height`/fit-to-content `viewBox`) — P3 · leverage L ÷ S

- **Motivated by:** `RenderToSvgOptions` has only `idGenerator` (`packages/ssr/src/index.ts:10-17`); C9's stated uses are thumbnails/OG images (`ROADMAP.md:531`).
- **Trade-off — building:** small, deterministic, golden-file-testable. **Not building:** every thumbnail pipeline post-processes the SVG itself.

### JSON import/export on components and `Upload` — P3 · leverage M ÷ S

- **Motivated by:** C11 JSON adapter reachable only below the component layer (`model.ts:85-103`).
- **Trade-off — building:** thin, reuses validate-first loading. **Not building:** JSON users hand-convert to XML.

## Product metrics to track (what & why — recommendation-only; placement → signal-map)

This is a client-side library with no telemetry of its own; metrics are read from the engine's event bus by the **host application** (`viewer.on(...)` / `get('eventBus')`). No values are reported — none were observed.

### Save / restore

- **Metric:** task success — share of `save` palette actions followed (same user, later session) by a successful restore; today structurally 0 because restore is unwired.
- **Why:** confirms whether "Save" delivers persistence users can rely on.
- **→ signal-map:** events at `LocalStorage.save`/`loadSaved` (`localStorage.ts:37,45`) — none emitted today.

### Undo / redo usage

- **Metric:** adoption + error-recovery rate — undo count per session, undo-after-mutation latency.
- **Why:** high undo right after a gesture flags confusing interactions (e.g. drag/resize).
- **→ signal-map:** read from `commandStack.changed` (already emitted, `CommandStack.ts:239`); no new code needed.

### Auto-layout

- **Metric:** adoption + task success — `autoLayout()` invocations and the share immediately undone.
- **Why:** an immediately-undone layout means the solver's output was rejected.
- **→ signal-map:** a layout-committed event at `Editor.autoLayout` (`packages/editor/src/index.ts:165`) — none today.

### Keyboard navigation (C2)

- **Metric:** activation — sessions where `keyboardNav` receives focus and moves selection at least once.
- **Why:** measures whether the a11y path is discovered and used.
- **→ signal-map:** a focus/nav event at `keyboardNav._onKeydown` (`keyboardNav.ts:113`) — none today.

### Document import health

- **Metric:** error rate — `importDiagram` rejections / total imports (XML and, if added, JSON).
- **Why:** adapters currently void import rejections, so broken documents fail silently (see Needs confirmation).
- **→ signal-map:** rejection sites at `packages/element/src/index.ts:65,89`, `packages/react/src/index.tsx:127-128`.

### Export format mix

- **Metric:** adoption — `pfdn` vs `svg` vs `png` exports.
- **Why:** prioritizes format work (JSON export, SSR sizing, PDF).
- **→ signal-map:** `Exporting.trigger(fileType)` at `packages/core/src/features/exporting.ts:42`.
