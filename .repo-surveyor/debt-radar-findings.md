## Swallowed / silenced errors

### `.pfdn` import rejections dropped with `void` — P2 · leverage H ÷ S

- **Evidence:** `packages/element/src/index.ts:65,89` — `void editor.importDiagram(...).then(() => this._updateFormValue())`; `packages/react/src/index.tsx:128` — `void editor.importDiagram(defaultValue)`; `packages/core/src/features/upload.ts:61` — `void this._host.importDiagram(xml)`.

## Latent risk

### Debounced property edit commits into the newly selected element — P1 · leverage H ÷ S

- **Evidence:**
  - Text inputs debounce `_applyChange(target)` by 300 ms (`packages/editor/src/properties-panel/PropertiesPanel.ts:184-189`).
  - On `selection.changed`, `_update(selected)` rebuilds `_entries` synchronously (`:131-147`, `:264`).
  - When the timer fires, `_commit` resolves `this._entries[<old input's name>]` (`:209-218`), which is now the newly selected element's entry. The timer is never cleared on selection or destroy.
- **Scenario:** type in a node's Name, then click empty canvas within 300 ms. The text is written to the diagram Settings `name`, or to any other element that has a same-named field.
- **Benefit of fixing:** closes a cross-element write, which is data corruption that undo can mask.
- **LOE:** S. Bind the target entry or definition at keystroke time, or flush the pending debounce on `selection.changed`; add a regression test.
- **Trade-off — not fixing:** silent wrong-element edits on a common flow. **Fixing:** flushing on selection commits the in-flight text one tick earlier, which is the expected behaviour.

### `Diagram.destroy()` tears nothing down — P2 · leverage M ÷ M

- **Evidence:**
  - `packages/core/src/Diagram.ts:74-76` only emits `d3canvas.destroy`, and core has almost no teardown (7 `.off(`/`.remove()` in all of non-test `core/src`).
  - Nodes that are never removed: the hidden `<a>` (`features/exporting.ts:85-93`), the `<input>` (`features/upload.ts:33-40`), the palette (`features/palette/Palette.ts:66`), and the aria live region (`features/ariaAnnouncer.ts:97`).
- **Benefit:** remount-safe components. This matters for React StrictMode and the custom element's connect/disconnect cycle.
- **LOE:** M. Per-module `d3canvas.destroy` handlers plus a leak test.
- **Trade-off — not fixing:** DOM and listener leaks on every remount. **Fixing:** many modules touched, though each change is mechanical.

### Adapter teardown during a pending import boots a destroyed editor — P2 · leverage M ÷ S

- **Evidence:** `packages/element/src/index.ts:65` and `packages/react/src/index.tsx:128` start an import that is not awaited. A disconnect, or React StrictMode's cleanup-then-remount, calls `destroy()` before the import resolves, and the pending import then runs `_boot` on the destroyed instance.
- **Benefit / LOE:** prevents a second engine or SVG being mounted in the host. S (a cancellation token). **Trade-off:** small added state vs duplicate canvases under StrictMode.

### Confirm dialog's `document` keydown listener outlives the editor — P2 · leverage M ÷ XS
